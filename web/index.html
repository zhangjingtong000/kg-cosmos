02 — 它真正量到了什么

63.6% 后面那句更该说的话

项目一度把「L5 = 63.7%」（旧读数，现为 63.6%）当作"关系证据支持度"对外报。做域内效度抽检后发现， 它只是判别器判通过的比例——200 条分层抽样、两个独立判定者 （一致率 86.7%，κ = 0.722）给出的真实读数是：

0% 三元组真被原文支持95%CI 34.1–46.0%
0% 判别器 PPV判通过的边里约一半不成立
0 域内加权 AUC官方校准集上是 0.9851
0 加权假阳性比真阳性（13778）还多

为什么要把这个写出来。它是项目里最不好看的一个结论—— 现成的 NLI 模型换到本任务的数据分布上会明显退化。

但它同时是最可复现的一条：抽检清单、盲判界面、加权脚本、 标注者一致性检验全在仓库里，任何人都能重跑一遍。

04 — 边界

它不声称自己是对的

前六层全部是自洽型判定——只说明图内部一致，回答不了"原文里的东西抽全了没有"。 所以补了 L9：从原文段落出发做独立标注。结果是分裂的： 端点召回 86.2%（实体名抽得还行），但 关系召回只有 42.9–57.1%。

而且这个区间必须这么报：关系抽取的评测本身比实体评测不可靠得多—— 同一批段落标注两次会差 25%。

已知的下一步：实测否决了"用本地模型重抽一遍"（本地产出只有云端的 1/5–1/10），所以这个短板目前没有便宜解法。
