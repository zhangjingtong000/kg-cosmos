## 一、为什么这份评测长这样（**不做主观打分**）

TODO 里 H11 的现状是：

> 用户明确说它是「项目设计最开始的主要看点」
> **只有 1 次成功记录**；分步接口的 2/3/4 步**从未实测**；
> **没有任何质量评测** —— "答得对不对"**没人量过** ⇒ ❌ **功能在、证据不在**

"答得好不好"没法机器判，**但它的几个必要条件可以**。
而且本项目有一个**硬约束**：

> **不能用 LLM 判分。** 已经量过：四个模型标注者对关系层的一致性 α 是**负的**
> （`RESEARCH_POINT_EVIDENCE.md` 证据一）。
> **用一个 α 为负的裁判去给另一个模型打分，得到的分数没有意义。**

⇒ 所以三个指标全部建立在**可机械核对的事实**上。

## 二、三个指标与结果

| 指标 | 怎么造题 / 怎么判 | 结果 |
|---|---|---|
| **① 召回** | 拿图里**真实存在**的实体名造问句，看它是否成为检索种子 | **78.3%**（47/60） |
| **② 拒答** | 拿**伪词**（随机字母+数字，已核对不在图内）造问句，看是否如实报"没有证据" | **100%**（60/60） |
| **③ 引用可核验率** | 每条证据 `citations[].paper/page` 是否指向**真实存在的论文与页** | **100%**（891/891） |

**② 是最要紧的**：一个问答系统的可信度，首先取决于**它不知道时会不会承认**。
**这一条完全可机器验证** —— 造一个图里绝无可能存在的字符串，
如果它还给出"结论"，那就是在编。**实测 60/60 全部如实拒答。**

**③ 说明引用是真的**（不是编的页码）。
`known` 集合 = 17 个图快照 + 2 个 gold 摘录 + **28 个上传任务的原始 PDF**。

## 三、★ 21.7% 的召回失败：**一个可修的根因**

13 题失败的**共性非常清楚**：

```
'Ningyu Zhang'                        → 种子 ['Zhang et al.', 'Wei Zhang', 'Yue Zhang', …]
'machine learning'                    → 种子 ['deep learning models', 'neural machine translation', …]
'scientific literature analysis'      → 种子 ['ArXiv', 'SciBERT', 'IEEE Access', …]
'reasoning strategies'                → 种子 ['KGs', 'knowledge-guided reasoning', …]
'rule-based methods'                  → 种子 ['Large Language Model', 'Recommendation systems', …]
'B. K.'                               → 种子 []（长度不足）
```

**⇒ 根因：`multi_agent_qa.retrieve()` 的种子匹配是「词级匹配」，不是「整串匹配」。**

它的实现是：
```python
q_tokens = [t for t in re.split(r'[^0-9A-Za-z\u4e00-\u9fff]+', question.lower())
            if len(t) >= 2]
# 用这些 token 去和实体名/描述做词级匹配
```

**⇒ 于是 `'Ningyu Zhang'` 被拆成 `['ningyu','zhang']`，而 `zhang` 这个 token
在语料里命中了几十个不同的人**（`Wei Zhang`、`Yue Zhang`、`Wentao Zhang`…），
**真正的 `Ningyu Zhang` 反而没进种子**。

**⇒ 这不是"抽得差"，是"检索口径"的问题，而且有明确的修法**：

| 修法 | 说明 |
|---|---|
| **① 整串优先** | 先在问题里找**完整实体名**（`PathQA` 就是这么做的：`ql.includes(id)`），命中就占满种子位 |
| **② 长 token 优先** | 现在按"图上度数"排序；应改成**先按 token 长度/整串匹配程度**排序 |
| **③ 常见 token 降权** | `zhang`/`learning`/`methods` 这类在语料里出现极频繁的 token，命中时降权（类 IDF） |

**⇒ 但这次我「只评测、不改」** —— 因为**改检索会改变回答内容**，
而那是"会打破绿灯"的改动，按纪律要留 before/after 双口径。
**这份评测就是那个 before。** 改完可以重跑它，直接看出提升多少。

## 四、诚实的边界

| # | 边界 | 影响 |
|---|---|---|
| **1** | **只测了 1 张图**（`ad690dfb`，上传的 `2506.09566v1`） | 换一篇，召回率的绝对值会变；**但"token 匹配导致常见词胜出"这个机制与图无关** |
| **2** | **60 题/类** | 召回率的 95% 置信区间约 ±10 个百分点；**78.3% 是点估计** |
| **3** | **② 用的是"伪词"** | 它测的是"**明显无关的东西**是否被拒"，**不是"沾边但错误的东西"是否被拒** —— 后者更难，也更危险 |
| **4** | **③ 只验"来源与页码是否存在"** | **不验"引文是否真的支持那条边"** —— 那需要读原文（L5 判别器在做，PPV 49.7%） |
| **5** | **没测 2/3/4 步（支持/反对/综合）的质量** | 那三步要调本地模型，**而且它们的好坏正是"α 为负"那一层的难点**。TODO 里"分步接口的 2/3/4 步从未实测"这条**仍然成立** |

**第 5 条要特别说清楚**：本次评测**只覆盖了第 1 步（检索）的质量**。
**"多 Agent 辩论"本身的质量仍然没有证据** —— 那是这份评测的**边界，不是它的成就**。
