## 一、先说**最硬的那条**：neo4j 那套已经不在了

实测（2026-09-17）：

```
7687 端口（neo4j bolt）  ❌ 没有监听
7474 端口（neo4j http）  ❌ 没有监听
```

而 `docker-compose` 要起的第一件事就是 `neo4j`。
今天这套系统**跑的是内存版**：

```python
# src/app.py:113-120
"""Neo4j when configured and reachable; NetworkX keeps /upload working."""
if os.environ.get("KG_BACKEND", "neo4j") == "neo4j":
    ...
    uri=os.environ.get("KG_NEO4J_URI", "bolt://localhost:7687"),
```

⇒ **写一个 compose 文件去起一个"已经不参与运行"的服务**，
不是部署，是**给已经不存在的依赖补一份说明书**。

**（顺带）**：`docker-compose` **只在有 Docker 的机器上才有意义**，
而演示机是**固定的这台**（下面第二节）—— 它没有 Docker。

## 二、GPU 模型这一条：**compose 起不来 8 GB 显卡上的 Ollama**

本项目要跑的是 `qwen3.5:9b`（**6.14 GB**）+ `bge-m3`。
在 **RTX 4060 Laptop 8.0 GB** 上：

```
模型常驻占用 6496 / 8188 MiB = **79%**，只剩 1692 MiB
（C3 那次的实测；见 docs/C3_OLLAMA_500_ROOT_CAUSE.md）
```

**⇒ 把它塞进容器，要处理的是**（每一条都是真实工作量）：

1. **NVIDIA Container Toolkit** —— 宿主机要先装，且版本要与驱动匹配；
2. **显存分配** —— 容器内可见的显存与宿主机一致性，
   **而我们已经只剩 1692 MiB 余量**（C3 怀疑就是它导致的 500）；
3. **模型卷** —— Ollama 的模型目录要挂出来，否则每次重建容器**重下 6 GB**；
4. **`--gpus all`** —— 而这台机器是**笔记本**（混合显卡 + 节能模式会让它更不稳）。

**⇒ 结论：把"本机可跑的 GPU 模型"做成 compose，是在给一个
"本来就在本机跑得好好的东西"增加一层会失败的抽象。**

## 三、这个项目**本来就不是给服务器部署的**

它的三个特征都指向**单机**：

| 特征 | 说明 |
|---|---|
| **数据在本机** | `data/corpus/` 28 个 PDF、`data/corpus/graphs/` 17 个图；**`data/` 在 `.gitignore` 里**（N6/P13） |
| **模型在本机** | Ollama + `qwen3.5:9b`；**全程零 API 成本**（余额 ¥3 的约束下这是设计前提） |
| **前端就是静态文件** | `web/` 由 `src/app.py` 直接挂载（**8000**），也能用 `tools/serve.py --static`（**8098**）只发静态 |

⇒ **"部署到服务器"这个问题的正确答案，对这个项目是**
**"它不是服务器应用"** —— 而不是"我给你写个 compose"。

## 四、那"怎么部署"到底怎么说（**可以直接用的话术**）

> 「这个系统是**单机研究工作台**：语料、模型、产物都在本机。
> 换台机器要做的不是 `docker compose up`，而是**三步**：
> ① `pip install -r requirements.txt`；
> ② `ollama pull qwen3.5:9b`；
> ③ `python src/app.py`。
> **这套流程在 `REPRODUCE.md` 里逐条写着**，
> 而它比 compose 文件更可靠 —— 因为**它是真的跑过的**。」

**⇒ 而"可复现"这件事本项目的答卷不是 compose，是**：
- `REPRODUCE.md`（重建步骤）· `tools/verify_all.py`（**50 项可重跑的检查**）·
  `METRIC_CALIBERS.md`（口径册）。

**⇒ 用"能重跑"回答"怎么部署"，比用一份没人验证过的 compose 文件诚实。**

## 五、我**没有**做的事（说清楚，别让人以为漏了）

- **没有**写 `docker-compose.yml`（理由见上）；
- **没有**删掉代码里的 neo4j 分支（**它在 `KG_BACKEND=neo4j` 时仍是一条真实路径**，
  而且 `src/app.py:113-120` 那段注释已经说明了它的地位）——
  按 `ARCHIVE_POLICY`，**被替代的东西不删**；
- **没有**改端口、没有动 `tools/serve.py`（那两个服务当前都在跑，
  且 `check.ps1` / `verify_all` 依赖 8000）。

## 六、如果将来真要做，需要什么

| # | 前置 |

| 5 | **`data/` 不在 git 里** ⇒ 镜像里没有语料，**必须挂载**（这一点最容易漏） |

**⇒ 这五条都是"要真做才知道"的，而它们与演示无关** ⇒
**这一项到此为止，登记为"不做，理由已成文"。**
