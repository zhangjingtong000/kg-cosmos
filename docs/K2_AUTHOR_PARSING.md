## 二、★ 为什么不直接写进注册表

N7 已经把这条纪律定死了（`docs/N7_WHAT_IS_A_PAPER.md §三` 洞 1）：

> **作者缺失** —— `_manifest.json` 里没有 `author` 字段 ⇒ 注册表里**如实留 `None`**，
> **不去猜**。要补得从 PDF 首页解析。
> **猜出来的作者比没有更糟。**

**⇒ 所以本脚本的产物是「候选 + 置信度 + 依据」**，
让人和页面**复核之后**再决定要不要写进去。
**一个错的作者会污染引用**，而"没有作者"只是一个空洞。

## 三、判据：**用版面，不猜文字**

**不是**"找一行像人名的文字"，而是用 arXiv 论文首页的**版面结构**：

```
实测（2402.12001v1，页面 612×792）
14.3  A Survey on Extractive Knowledge Graph Summarization:   ← **标题（最大字号）**
12.0  Xiaxia Wang            8.0 2                           ← **作者（次大 + 上标）**
12.0  xiaxia.wang@cs.ox.ac.uk, gcheng@nju.edu.cn             ← **邮箱（极强信号）**
12.0  Abstract                                               ← **边界**
```

四条信号：
1. **边界**：`Abstract` / `Introduction` 所在的行 —— 作者一定在它**之前**；
2. **字号**：**明显大于正文、且小于标题**的那些行才是候选区；
3. **人名样式**：按 `,`/`;`/`and`/`&` 切开，每段 2–4 个词、首字母大写、
   允许尾随上标；**保守**（排除机构词与邮箱，"宁可漏，不可错"）；
4. **邮箱**：同区出现 `@` ⇒ **这是"作者区"的铁证**。

### 置信度

| 分 | 依据 |
|---|---|
| **0.95** | 该区出现邮箱（`@`），且切出 ≥2 个合规人名 |
| **0.85** | 无邮箱，但字号严格小于标题，且 ≥2 个合规人名 |
| **0.60** | 无邮箱且字号层次判不出，但切出合规人名 ⇒ **只能当线索** |
| **0.00** | 切不出任何合规人名 ⇒ **如实说"没解析出来"** |

## 四、⚠️ 开发中踩的三个坑（**都记在这里，因为它们解释了为什么只有 43%**）

### 坑 1：`max_size` 取到了**页眉水印**的字号

第一版用"全页最大字号 = 标题"。实测：

```
1703.08098v9  字号集 [20.0, 14.3, 12.0, 10.9]
              ⇒ 20.0 是 **arXiv 侧边水印**（只出现 1 次，**不在页眉页脚位置**，
                坐标过滤也挡不住）
              ⇒ max_size=20.0 ⇒ "标题"被判成次大字的正文
              ⇒ zone 里只剩标题本身 ⇒ **切不出人名、整篇 0.00**
```

**修法**：**标题字号 = 在"明显大于正文"的字号里，出现次数最多的那个** ——
标题**跨行** ⇒ 出现 2+ 次；水印通常是**孤零零一行**。（实测：20.0×1 行 vs 14.3×**2 行**。）

**⇒ 效果：5/28 → 13/28。**

### 坑 2：**标题的续行**被误判成人名

修好坑 1 之后冒出 6 个 **0.60 假阳性**，全是标题的续行：
`Survey Article Tables` · `Future Directions` · `Representation Learning` ·
`Knowledge Graphs` · `Scalable E-Commerce` · `LLM-EMPOWERED …`。

**根因**：期刊排版里**续行的字号常常略小于标题首行**，所以"字号 < 标题"挡不住它。

**修法**：**该行的词有 ≥60% 出现在标题里 ⇒ 判为续行**。

### 坑 3：**高置信度的假阳性**（最坏的一种错）

```
✗ 2406.08223v2  0.95  "Université Paris Cité, New York"
```

**那是机构 + 地名**，却因为"同区有邮箱"拿到了 **0.95** ——
**错得最有把握**。而 `Université` / `Cité` 这种非英语词，**词表注定列不完**。

**修法**：扩词表（`université` / `cité` / 地名…）⇒ 这一条不再出现。
**但这一类不可能根治**：**规则法无法区分"非英语人名"与"非英语机构名"。**

## 五、⚠️ 已知的局限（**如实列出**）

| # | 局限 | 说明 |
|---|---|---|
| **1** | **11/28 解析不出** | 这些 PDF 的首页结构与 arXiv 常规版面不同（双栏 / 作者在页边 / 首页是封面）。**"解析不出"是答案，不是失败。** |
| **2** | **0.60 那 5 篇只是线索** | 其中仍有假阳性（如 `Information Technology`）。**页面上必须标"只能当线索"。** |
| **3** | **尾随上标字母没去掉** | 实测 `Li Caia, Xin Maoa, Yuhao Zhoua` 里的 `a` 是 arXiv 的**上标字母**（不是名字的一部分）。正则 `RE_SUPER` 在**单独测试时是对的**（`Li Caia`→`Li Cai`），**但那一处在实际流程里没生效** —— **已知未修**。⚠️ 所以 0.85 那档里的人名**可能多一个尾字母**。 |
| **4** | **没有做"作者 ↔ 机构"的对应** | 上标数字（`1`/`2`）本来是作者与机构的连接键，本脚本只取作者，**没建这个映射**。 |
| **5** | **只读首页** | 有些论文的作者在第二页（首页是图或摘要页）。**没往下翻**（翻页会引入更多误判）。 |

**⇒ 第 3 条要特别说明**：**它不是"没做"，是"做了但没生效，且没查清"**。
**在一个"候选 + 置信度"的产物里，这可以接受**（0.85 已经标了"要复核"）；
**但如果将来要把它写进注册表，必须先修掉它。**

## 六、它对 K2 的实际意义

**注册表里的 `author` 字段仍然是 `None`** —— 这是刻意的。
而这一页给 K2 提供的是：

| K2 的一个问题 | 这份产物的回答 |
|---|---|
| 元数据能不能自动补全？ | **部分能**（12/28），而**另外 16 篇要靠人** |
| 补全的结果可信吗？ | **每一篇都带置信度与依据** —— **页面按档位显示** |
| 能不能直接写进注册表？ | **不能**（N7 的纪律）⇒ 要么人工确认，要么页面上标"候选" |

**⇒ 而"43% 能自动补全"这件事本身是一个有用的结论**：
它说明**作者不是"再写个正则就有"的东西** ——
**这正是 N7 说"元数据解析要半天"时没说清的那部分。**

## 七、怎么用

```powershell
python tools/probe_authors.py                    # 全部 28 篇
python tools/probe_authors.py --id 2402.12001v1  # 看一篇的细节
python tools/probe_authors.py --min-conf 0.85    # 只看可信的
```

产物 `data/quality/author-candidates.json`：
```json
"2402.06861v2": {
  "candidates": ["Yansong Ning", "Hao Liu"],
  "confidence": 0.95,
  "why": "有邮箱 + ≥2 个合规人名",
  "evidence": ["作者区字号 12.0 < 标题 14.3", "作者区出现邮箱（@）", "候选区 3 行，切出 2 个合规人名"],
  "title_size": 14.3, "author_zone_size": 12.0, "has_email": true, "zone_lines": 3
}
```

**⇒ 每个分数都能顺着 `evidence` 复核** —— 那是这个产物值得存在的理由。
