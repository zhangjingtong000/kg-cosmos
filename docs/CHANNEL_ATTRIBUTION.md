# 通道差异归因：为什么本地 9B 的实体 F1 高于云端大模型

> 起因：2026-09-10 的评分显示本地 `qwen3.5:9b`（0 元）的实体 F1（0.624）高于云端
> `DeepSeek-V4.1-Flash`（0.403）55%。用户要求"具体查清原因，避免后续返工"。
> 本文记录完整归因过程与结论，供论文实验章与演示使用。

## 1. 先排除的三种"假解释"

| 假说 | 检验 | 结论 |
|---|---|---|
| **分布效应**（本地优势只来自某些页） | 按页统计两通道精度 | **否定**：本地在 1-6 页（0.64 vs 0.40）、7-12 页（0.46 vs 0.22）、13+ 页（0.08 vs 0.03）**逐段领先**，是系统性差异 |
| **解析器把脏数据塞进云端** | 查 `data/distill/entities.jsonl` 的云端原始响应 | **否定**：纯数字实体名（`2015`、`2012` 等 40/5574 行）与类型名本身（`Concept`、`Person` 等 43 行）**确由模型产出**，非解析器引入 |
| **本地只是抽得少所以精度高** | 对比两通道在相同区间内的输出量与命中数 | **部分成立但不足以解释**：本地输出是云端的 0.49 倍，命中是 0.74 倍，故精度（每单位输出的命中率）提升幅度超过规模补偿 |

## 2. 关键实验：四组对照（同时隔离 prompt 与模型）

同一篇、同一分块（1-5 页 10 块）、同一解析器，四组配置：

| 配置 | 实体行 | 去重 | 金标命中 | 耗时 | 成本 |
|---|---|---|---|---|---|
| A 云端 + 云端 prompt | 116 | 77 | **24** | 27s | ¥0.013 |
| B 本地 + 本地 prompt | 56 | 43 | 19 | 123s | ¥0 |
| C 云端 + 本地 prompt | 0 | 0 | 0 | — | — |
| D 本地 + 云端 prompt | 0 | 0 | 0 | — | — |

**C/D 双双失败**，原因很重要：
- 云端拿到本地 prompt（要求 JSON 输出）后返回 JSON，`parse_entities`（按 `<|>` 行格式解析）拿到 0 条
- 本地 9B 拿到云端 prompt（要求 `<|>` 行格式）后不返回合法 JSON，`call_ollama_json` 直接抛错

**结论：两个通道的 prompt 与其输出格式强绑定，不可互换。** 因此"同一任务定义下比较模型"
在本项目里无法直接构造 —— 这本身是必须写进论文的对比设计限制。

**注意 A/B 的样本结论与全篇相反**（A 命中 24 > B 命中 19）：因为该样本仅 10 块且集中在
1-5 页，而按页看第 2、3、6 页云端精度仅 0.22-0.28。**这是"小样本 + 页间方差"造成的
假象，不是真实反转** —— 也说明后续任何抽样对比都必须覆盖全篇或分层抽样。

## 3. 真实机制（三个叠加因素）

本地优势的来源是**精确率**（1-12 页：本地每单位输出命中 0.55 vs 云端 0.39），由三因叠加：

1. **JSON schema 约束（主因）**：本地走 Ollama 结构化输出，模型只能在给定 schema 内填值，
   天然排斥 `2002`（年份）、`Concept`（类型名本身）、`10.1101/2020...`（DOI）这类值；
   云端走自由文本行格式，无此约束。
2. **9B 模型的保守倾向（次因）**：倾向于少输出、只报最明确的实体
   （本地 1-12 页输出 141 条，云端 344 条）。
3. **金标判定风格与本地同向（最关键的方法论限定）**：本项目金标要求"论文**阐述**的对象"，
   按规则排除论文结构词、示例数据、纯统计量（见 `GOLD_ARBITRATION_RULES.md` §2）；
   而云端 prompt 要求"抽所有**明确提到**的实体"。**两者是两个不同的任务定义**，
   金标只对应后者中的一部分。

## 4. 因此，结论必须这样表述（论文口径）

✅ **可以声称**：
- 本项目的抽取任务下，本地 9B 通道的实体 F1 高于云端大模型 55%，**且零 API 成本**
- 该优势在论文各段落上一致（按页分层均领先），不是页面分布造成的
- 优势来源是精度：结构化输出约束 + 模型的保守倾向，使输出更贴合"知识实体"而非"所有名词"

❌ **不能声称**：
- "9B 模型的能力强于大模型" —— 本实验对比的是**端到端配置**（模型 + prompt + 输出约束），
  不是模型本身。云端的低精度中，有相当部分来自"要求它多抽"这一任务定义，而非能力不足
- 绝对 P/R/F1 可直接跨通道引用 —— 两通道任务定义与输出格式不同，绝对值不可比

📌 **应当补充的对照**：
- **分层报告**：给出"共同命中（两通道都抽到且正确）"与"任务定义差异项（有原文依据但金标
  按规则不收）"两类，让差异的来源可见
- 若需"同一任务定义下"的模型对比，必须统一 prompt 与输出格式（如都走 JSON 结构化输出），
  且需验证 9B 对同一格式的遵循率 —— 这是 A/B 反例（C/D 失败）已经说明的约束

## 5. 对项目决策的影响

1. **成本问题彻底消解**：本地通道零 API 成本且质量更优，后续论文可全部本地跑
2. **演示"离线演示"升级**：不再是降级兜底，而是**质量更优的首选方案**
3. **蒸馏的目标要改**：原计划"用云端数据蒸馏本地模型以接近云端"的前提**已被否定**
   （云端实体质量更差）。真正值得蒸馏的靶点是**关系抽取**：两篇的关系 F1 均 < 0.06，
   且两通道都差 —— 这是共同短板。（待用户确认后再动手，不自行决定。）
4. **评测口径必须分层**：单一 P/R/F1 数字会掩盖任务定义差异，必须连同一致率与
   显著性指标一起报告。
