## 二、判据原样

`tools/l5_report.py`：
```python
l3 = sum(1 for e in rows if e['source'] in all_names and e['target'] in all_names)
```

**`in` 就是集合成员判定** ⇒ 两个名字**差一个空格、差一个大小写**就判"端点缺失"。
⇒ 这正是 `OPTIMIZATION_RANKING` 说"缺口全部来自字符串失配"的依据。

## 三、实测结果

```
严格判据（原样）  42186 / 43867 = **96.1680%**
归一化判据        42285 / 43867 = **96.3936%**
⇒ **+0.23pp**      （预估 +8.16pp，**差 35 倍**）
```

### ★ 为什么差这么多：**收益被另一件事吃掉了**

```
OPTIMIZATION_RANKING 排第 1 名时（2026-09-14）：L3 = 68.44%
而 backfill_missing_endpoints.py 把 L3 提到了 96.2%（端点反建）
⇒ 等到今天真去做归一化，台阶已经被别人占了
```

**⇒ 这不是"方案错了"，是"排序表的有效期过了"。**

### ★ 缺口构成也推翻了原判断

```
原缺口 1681 条
  · 归一化能救回：   99（5.9%） ← **纯排版差异**
  · 救不回：       1582（94.1%）← **不是排版问题**（真缺失 / 别名 / 复数）
```

原文说「缺口的 **8.16pp 全部来自字符串失配**」——
**对现在的数据，94.1% 的缺口不是排版问题。**
⇒ **同一句判断，在不同时间的同一条指标上，结论可以相反。**

## 四、⚠️ 归一化安不安全：量了，但**不替人下判断**

归一化会把一些名字合并到同一个 key 下：
```
被合并的组：678 组（1382 个名字）
其中"大小写之外还有别的差别"的组：**57**
  'fine tuning'            ← ['Fine-Tuning', 'Fine Tuning', 'fine-tuning']
  'instruction tuning'     ← ['Instruction-Tuning', 'Instruction Tuning']
  'real time'              ← ['Real Time', 'Real-time', 'Real-Time']
  'low dimensional vector' ← ['Low Dimensional Vector', 'Low-Dimensional Vector']
  'president of'           ← ['President Of', 'president-of']     ← ⚠️ 这个像抽取碎片
```

**那 57 组从样例看大多是排版差异**（`Fine-Tuning` 与 `Fine Tuning` 是同一个东西），
**但我不替它下判断** ——
`'president of'` 那一组看起来就是**抽取碎片**，
**"哪些该合"需要人过一遍**（这是 B4 已经吃过一次亏的地方：
本项目的消歧判据被量出 **27.4% 的假阳性**）。

**⇒ 所以结论是：并列，不替换。**

## 五、做了什么，没做什么

**做了**：
- 复现原判据（`in` 精确匹配），拿到 **96.1680%**；
- 实现**保守归一化**（只吃排版差异：大小写 / 空白 / 下划线连字符）；
- 量出 **+0.23pp**，并**定位到"收益被端点反建吃掉"**；
- 量出**归一化的合并风险**（57 组需人工确认）。

**没做（刻意）**：
- **没有把归一化接进 L3 判据** ——
  收益只有 +0.23pp，而风险不是零（57 组待确认）。
  **为一个 0.23pp 的收益去动一个被反复引用过的口径，不值得。**
- **没有替换 `L3_endpoints` 的原值** ——
  **原数是别人引用过的，换掉它会让六层指标不可比**（A3 那次的纪律）。

## 六、★ 这一项真正的产出：一条方法论

**优化项的收益不是常数，它随别的改动衰减。**

```
2026-09-14 排序时：L3 归一化 = +8.16pp（第 1 名）
2026-09-16 真去做：+0.23pp（连前 5 都排不进）
中间的变量：端点反建把 L3 从 68.44% 提到了 96.17%
```

**⇒ 所以 `OPTIMIZATION_RANKING.md` 这类"收益排序表"必须带一个字段：
"这个数字是什么时候、在什么基线之上算的"。**
否则**照着它做事的人会拿一个过期的数字去争一个不值得的改动** ——
**而这正是 H10 这次真实发生的事。**

**这条与 A3 同源**：A3 是"名字与实际不符"，H10 是"**数字与时代不符**"。
两者都属于**"文档里的一句话，在某个时间点之后就不再为真"**。

## 七、诚实的边界

| # | 边界 | 影响 |
|---|---|---|
| **1** | **只量了"能不能救回边"，没量"救回的那 99 条边值不值得"** | 它们多半是**大小写差异的实体**（如 `García-Durán et al.`），本身可能是低质节点 |
| **2** | **归一化只做三种，没试更激进的** | 复数（`Models`/`Model`）、别名（`KG`/`Knowledge Graph`）**都没碰** —— 那是判据问题，不是排版问题 |
| **3** | **57 组合并风险只看了前 6 个样例** | **没有逐组人工过** —— 所以不能说"归一化是安全的" |
| **4** | **没有把归一化接进判据，因此"最后能拿多少"没有终值** | 拿到的是**上界**（+0.23pp 是"如果全接进去"） |
| **5** | **排序表里其余 13 项没重算** | **它们同样可能过期** —— 这一项只证明了"第 1 名过期了" |

**第 5 条最要紧**：**这一项证明了排序表会过期，但只证明了它的一条。
其余 13 项现在的实际收益是多少，仍然是未知数。**
⇒ 那需要**逐项重跑**，不是今天的范围。
