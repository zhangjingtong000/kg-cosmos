# 研究点的证据链（2026-09-15）

> **主研究点**：
> ## 「**可抽性 / 可标性取决于协议的结构化程度 —— 而它与表达力是同一条轴的两端**」
>
> **本文把四块证据摆在一起**，并写明**它修正了什么、以及诚实的边界**。
> 配套：`INNOVATION_AUDIT.md`（候选盘点）· `P6_SCIREX_RELATION_ANALYSIS.md`（P6 实测）·
> **`P3_PROTOCOL_LADDER_RESULT.md`（P3 协议阶梯，最强的一块）**。
>
> **★ 2026-09-15 更新：P3 完成后，主研究点从"两臂对照的观察"升级为"可归因的单调曲线"。**

---

## 证据零 ★★★ · P3 协议阶梯：**只改协议，α 从 −0.30 单调升到 +0.42**

**同一篇论文、同一个模型、同一批"标注者"，只换指令的结构化程度**：

| 档 | 协议 | α（填 0 口径） | 用到的类型数 |
|---|---|---|---|
| 1 | **完全开放** | **−0.2977** | **29** |
| 2 | 给类型表 | **−0.2209** | **10** |
| 3 | 类型 + 方向 | **−0.0243** | **9** |
| 4 | **槽位式**（SciREX 形态） | **+0.4179** | **3** |

**差值 `+0.0768 → +0.1966 → +0.4422`：不仅单调，而且增幅递增。**
"用到的类型数" 29 → 10 → 9 → 3 同步单调下降 —— 那是结构化程度的操作性度量。

**为什么它是最强的一块**：它**解决了原先证据一/二的两个问题** ——
① **只变一个变量**（协议），所以**可归因**，不再是"协议+标注者同时变"的观察；
② **四个档位**给出**曲线**，不再是"高 vs 低"。

⇒ **可以明确说：一致性的提升来自协议本身，而不是"换成人类标注者"。**

**边界**（详见 `P3_PROTOCOL_LADDER_RESULT.md §三`）：档 4 只有 **7 个单元**（最弱一环，
但那本身也是"窄协议抑制产出"的发现）；两个"标注者"是**同模型两个 seed**
（测的是采样噪声下界，不是两个独立标注者）；**人类两档（P2）还没做**。

## 证据一 · 标注侧：同一批标注者，实体层一致、关系层不一致

```
实体层  Krippendorff α = 0.2312（别名感知 0.2849）
关系层  α = −0.0119（另一篇 −0.1465）
```
**200 个关系单元里 135 个只有一票**（67.5%）—— 这不是"标准不一"，
是**根本标不出共识别的东西**。

⚠️ **诚实边界**：四个标注者是 **3 个 DeepSeek agent + 1 个 GLM，零人类**。
所以严格说，它证明的是「**LLM 标注者之间不一致**」。

---

## 证据二 · 对照侧：SciREX 用槽位式协议，人类标出了 2148 条

```
train 1627 + dev 251 + test 270 = 2148 条
槽位固定 {Method, Task, Material, Metric, score}
```

**⇒ "关系不可标注"这句话是错的。** 正确的是：
**可标性取决于标注协议的结构化程度。**

**A 与 B 之间同时变了两个变量**（协议：槽位式 vs 开放式；标注者：人类 vs LLM），
所以**补臂 C（人类 + 我们的开放式协议）仍然需要** —— 那是 D1/D3 的价值。

## 证据三 · ★ **反向验证（P5）**：槽位化不是免费的

**本体的 16 类关系里，只有约 1/3 能塞进那四个槽位**（全量 43867 条边）：

| 可槽位化（**33.6%**） | 条数 | 占比 | 映射 |
|---|---|---|---|
| `USES` | 7339 | 16.73% | Method → Material |
| `APPLIES_TO` | 3850 | 8.78% | Method → Task |
| `PRODUCES` | 2213 | 5.04% | Method → Artifact |
| `MEASURES` | 872 | 1.99% | Method → Metric |
| `EVALUATES` | 454 | 1.03% | Method → Metric |

| **塞不进（约 66%）** | 条数 | 占比 | 为什么 |
|---|---|---|---|
| `RELATED_TO` | 9598 | 21.88% | 无类型，本身就不是一个确定的关系 |
| `CREATED_BY` | 8755 | 19.96% | 归属（谁写的），**文献计量**不是实验装置 |
| `PART_OF` | 5816 | 13.26% | 结构包含（层级），四槽位里没有"部分-整体" |
| `ENABLES` | 999 | 2.28% | 能力使能 |
| `CITES` | 967 | 2.20% | 引用，**文献计量** |
| `LOCATED_AT` | 853 | 1.94% | 位置 |
| `SUPPORTS` | 793 | 1.81% | **态度（支持）** |
| `COMPARES_WITH` | 598 | 1.36% | 对比（勉强可算两个 Method 对同一 Task，但不是原生形态） |
| `CAUSES` | 280 | 0.64% | 因果 |
| **`CONTRADICTS`** | **243** | **0.55%** | **态度（矛盾）—— 争议视图的基础** |

**⇒ 丢掉的恰是本项目最有特色的部分**：
`CONTRADICTS`（矛盾视图）、`SUPPORTS`、`CITES`（引文网络）、
`CREATED_BY` / `PUBLISHED_IN`（文献计量，是接元数据 API 的接口）。

> **P5 的意义不是"证明应该槽位化"，而是把结论从"单方面推荐"变成"有取舍的设计空间"。**
> 原先只说「越结构化越可标」，那像是在推荐槽位化；
> **加上这个反向验证之后，它描述的是：**
> **"可标性"与"表达力"是同一个协议设计的两端 —— 想提高一端，就得放弃另一端。**

## 四块证据合起来说了什么

```
                 协议结构化程度 低 ←──────────────────→ 高
  表达力                     高                        低
  可标性                     低                        高
  ────────────────────────────────────────────────────────
  ★ P3 实测（同模型/同语料/只改协议）
      α                  −0.30  −0.22  −0.02  +0.42     ← 单调
      用到的类型数           29     10      9      3      ← 单调
  ────────────────────────────────────────────────────────
  本项目（开放 16 类）      ✅ 选这一端
  SciREX（固定四槽位）                          ✅ 2148 条人类一致标注
  ────────────────────────────────────────────────────────
  证据三（P5）：槽位化只能覆盖我方 33.6% —— 丢掉的恰是
      CONTRADICTS（争议视图的基础）· SUPPORTS · CITES · CREATED_BY
```

**⇒ 本项目关系层 α = −0.0119 的完整解释**：

> **不是"我们标不出来"，而是"我们选了一个更难但更 expressive 的协议"。**
> **SciREX 之所以能一致，正因为它选了窄的那个。**
> **而 P3 在只改协议的前提下复现了这条规律** —— 一致性随结构化程度单调上升。

**这比"越结构化越可标"更有分量** —— 因为它同时解释了：
① 为什么我们的关系层不一致；② 为什么 SciREX 一致；③ **代价各是什么**；
④ ★ **而且第 ① 条现在是可归因的（只变了一个变量）。**

## 还缺什么（诚实的边界）

| # | 缺什么 | 为什么重要 | 谁能做 |
|---|---|---|---|
| **1** | **臂 C：人类 + 我们的开放式协议**（D1/D3） | A/B 之间同时变了两个变量（协议 + 标注者）⇒ **现在只能说"观察"，不能归因** | **用户**（1–2 小时 + 50 分钟） |
| **2** | **P3 扩样**（换 2–3 篇再跑） | **档 4 只有 7 个单元，是当前最弱的一环**，而它恰是曲线右端点的支撑 | 我（约 1 小时/篇） |
| **3** | **P2：人类标首尾两档**（档 1 与档 4） | 校准"LLM 曲线是否可信" —— P3 的两个"标注者"是同模型两个 seed | **用户**（约 1 小时） |
| **4** | **P4：真的把本体槽位化一次**，前后各标一轮 | 从"观察"变成"**可操作的设计原则**"（给出提升幅度） | 我（1 天 + 半天机器） |
| **5** | ✅ **P3 协议阶梯** | **已完成** —— α 从 −0.30 单调升到 +0.42（见 `P3_PROTOCOL_LADDER_RESULT.md`） | ✅ |
| **6** | ✅ **P5 反向验证** | **已完成** —— 槽位化只能覆盖 33.6% | ✅ |
| **7** | ✅ **P6 关系层**：TP = 0 的根因 | **已查明**（两边对"实体"的定义不同）；**不要报成"我们关系抽取 F1 = 0"** | ✅ |

**建议顺序**：**P3 扩样 → P4 → 臂 C + P2（用户）**。
理由：P3 扩样补的是**曲线最弱的一点**；P4 把它变成**可操作的设计原则**；
而**臂 C 与 P2 都只需要用户各花约 1 小时**，可以合并在一次。

## 一句话（可直接写进论文的"研究过程"）

> 我们最初的设计是"三通道抽取对比 + 人工金标算 P/R/F1"。
> **这个设计被我们自己的数据证伪了** —— 四个模型标注者对关系层的一致性 α = −0.0119，
> 而实体层有 0.2312。一度误判为"关系不可标注"。
> 但 **SciREX 用槽位式协议标出了 2148 条人类一致标注**，说明问题不在"关系"，
> 而在**协议**。进一步的反向验证（P5）显示：**那四个槽位只能覆盖我们
> 33.6% 的关系类型，其余 66% 塞不进去** ——
> **"可标性"与"表达力"是同一条轴的两端，我们选了表达力那一端。**
