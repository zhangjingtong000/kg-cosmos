## 二、★ 先量，再决定给人看什么

17 篇两两对比（**136 对**）：

| 量什么 | 结果 |
|---|---|
| 节点重叠（Jaccard） | **最高只有 0.089** —— 同领域两篇，共享实体最多 546 个 |
| **节点交集为空的对** | **0 / 136** —— **每一对都有共享实体** |
| **关系交集为空的对** | **28 / 136** —— 但有 28 对**没有一条相同的关系** |

**⇒ 后一条才是看点**：**两篇共享了实体，却没有任何一条相同的关系** ——
即「**同一批东西，两篇给出的关系不一样**」。
共享实体是显然的（同领域必然有共同概念），**关系怎么不同才是信息。**

## 三、页面给三样东西

1. **实体三栏**：只在左 / 共有 / 只在右（附 Jaccard）；
2. **共有关系**：两端都在交集里的边，**按实体对归纳**，
   `左篇类型` 与 `右篇类型` **并排列出**（两个色块）——
   并统计"类型一致 / 类型分歧 / 只有一篇有"各多少对；
3. **「值得看的对」**：把 28 对**共享实体、零共享关系**的直接列出来，
   点一下就切过去。**不让人自己去 136 对里找。**

### ⚠️ 「类型分歧」**不等于矛盾**

同一对实体在两篇里类型不同（一篇 `USES`、一篇 `BREAKS_DOWN_INTO`），
**可能是两篇在说不同的侧面**。本项目**没有做"这两条边冲突吗"的判断**
（那需要读原文）。⇒ 所以叫「**类型分歧**」，页面上直接注明。

**这与 P7 的矛盾视图是同一条纪律**：**能看到的差异，不等于判定为冲突。**

## 四、★★ 一个自己踩到并修掉的坑：截断让指标失真

**第一版**把每篇的节点按 `max_list=400` 截断（为了控制文件体积）。
跑出来 **J 从 0.089 掉到 0.072** ——
**因为截断是按字典序取前 400，交集就算不准了**，
而"重叠多少"**正是这一页要给人看的数**。

⇒ **宁可拆文件，也不截断**：
```
diff.json          19 KB（索引 + 136 对摘要）  ← 首页只加载这个
diff/<论文>.json   17 个 · 平均 148 KB          ← 选了哪两篇才取那两个
```

**这个坑的教训是通用的**：**为了让产物变小而截断，会改掉指标本身** ——
如果那个指标是页面存在的理由，**那就是把功能做坏了而不只是变慢了**。

## 五、★★ 最强的那条断言：**在 Python 里独立复算**

浏览器实测（`tools/cdp_verify_diff.py`）七组，其中第 3 组是核心：

> **在 Python 里独立算一遍交集，与浏览器算出的 KPI 逐字相等**：
> ```
> DOM KPI: {'nInter': '546', 'nJ': '0.0887', 'nEInter': '257'}
> Python ：共有实体 546 · J=0.0887 · 共有关系 257
> ```

**为什么这条最强**：「页面渲染出来了」是**弱**断言——**渲染一个错的数也算渲染**。
而这一页的核心输出是**交集的规模**，那**可以在浏览器之外独立复算** ⇒
两边必须逐字相等。**这才证明"算对了"，而不只是"画出来了"。**

第 6 组顺带验证了那个形态本身：点「值得看的对」里的一条
（`2202.07412v1 × 2502.00681v2`）⇒ 切换后
**`n_inter_nodes=50 · n_inter_edges=0`** —— **正是"共享实体、零共享关系"**。

## 六、诚实的边界

| # | 边界 | 影响 |
|---|---|---|
| **1** | **"共有关系"只看两端都在交集里的边** | 若 A 有 `X→Y`、B 有 `X→Z`（`Z` 不在交集），**不算共有**，也不算分歧 —— 那类"跨出去的差异"这一页看不到 |
| **2** | **边的同一性用 `source\|target\|type` 精确匹配** | 实体名有大小写/别名差异时**会算成不同** —— 而 B4 已量过消歧判据的假阳性 27.4%，所以这里**没有做任何归一化**（归一化会引入它自己的错） |
| **3** | **「类型分歧」只比类型集合，不看证据** | 两篇给同一对不同的类型，**可能是同一件事的不同说法**；页面已注明"不等于矛盾"，但**没有进一步区分** |
| **4** | **列表上限 260 条**（实体）/ **24 条**（值得看的对） | 超出只报数量。**上限是硬编码的**，没有做成可调 |
| **5** | **没有人类判断"这些分歧有意义吗"** | 页面给的是**结构上的差异**，不是**语义上的冲突** |

**第 2 条值得记住**：**这里刻意不做归一化** ——
因为"归一化"本身需要判据，而**本项目的消歧判据已被量出 27.4% 的假阳性**（B4）。
**在一个已知会错的判据上加一层，只会让错更难查。**
⇒ 所以这一页给的是**原始形态的差异**，把"要不要归一"留给读者判断。

## 八、数字口径修订记录：28 → 87（2026-09-19）

**症状**：`web/kg-data/diff.json` 里 `design.measured.pairs_with_zero_shared_edges`
写着 **87**，而**同一个 `measured` 对象**的 `note` 却写「有 **28** 对」——
一份产物自己打自己的脸。而 `web/index.html` 恰好取了 `note` 里的 28，
于是**前端可见数字错了一整轮**，没有任何检查发现
（`tools/check_doc_numbers.py` 当时只盯 `data/quality/` 与语料篇数）。

**判定：28 与 87 是同一个口径，不是两个指标。**
两版都要求"两篇**有共享实体**、且**没有任何一条共享边**"。
差别只在**规模**：28 是 **17 篇 / 136 对**（2026-09-16）时的读数，
87 是 **21 篇 / 210 对**时的读数。
（顺带排除另一种可能：本项目**没有**"零共享实体对"这个指标 ——
实测每一对都有共享实体，`0 / 210`。）

**根因**：`tools/build_diff_data.py` 把 `note` 写成了**硬编码字符串常量**
（第 154 行原文「…有 28 对…」），而 `measured` 的其它字段是**现算**的。
语料涨了 4 篇 ⇒ 现算的字段自动变 87，字符串里的 28 不动。

**修法（三处）**：

1. `tools/build_diff_data.py`：`note` 改为由 `n_zero` / `max_j` **f-string 现算**；
   `design.why_not_precompute_all` 里的 136 / 17 同样改为现算；
   新增 `design.superseded_measurements` —— **把 28 与 136 连同口径、日期、
   被谁替代一起留档**（按 `docs/ARCHIVE_POLICY.md`：被替代的内容不直接删）。
2. `web/index.html`（卡片注释与可见正文）、`web/diff.html`（注释与正文）：
   数字统一为 87；`diff.html` 正文那句「N/M 对」**改为从 `diff.json` 现填**
   （`figMaxJ` / `figZeroNodes` / `figZeroEdges` / `figPairsA` / `figPairsB`），
   **页面不再保留第二份真相**。
3. 守门（见下）。

**守门加在哪、为什么**：加在既有的 `tools/check_doc_numbers.py`，
**不另写脚本** —— 它已是 `verify_all.py:145` 的统一入口，`web/index.html`
本来就在它的 `DOCS` 白名单里；另起一个脚本还要再接一次 verify_all、
再维护一份白名单，只会多一处漏。共三处：

- `DOCS` 增加 `web/diff.html`（此前它**不在**名单里 ⇒ ① 的旧值扫描扫不到它，
  与前一轮 `docs/verification.md` 的缺口同型）；
- `STALE` 增加**带分母的整串** `28/136` · `28 / 136` · `0/136` · `0 / 136`
  （为什么不用裸 `28` / `136`：裸数字在别处可能是别的量，会误报 ——
  这正是本脚本反复栽过的"过度收紧"与"形同虚设"之间的取法）；
- 新增 **⑧ 针对性断言**（三层）：**a.** `note` 里的数 == `measured` 里的数
  == 由 `pairs[]` **独立重算**的数（⚠️ 只比对两个字段不够 ——
  两个字段一起错就查不出来）；**b.** `web/index.html` 的可见写法
  「N 对是「共享实体、零共享关系」」必须等于产物值；
  **c.** `web/diff.html` 可见正文不许再出现写死的 `N/M 对`，
  且五个填充锚点必须存在（这一条**不依赖具体数值** ⇒ 对数再变仍有效）。

`tools/cdp_verify_diff.py` 同步加**第 7 组**断言：页面上那句「N/M 对」的
**DOM 值必须等于索引里的值**（此前第 5 组只看按钮条数，不看这句话）。
