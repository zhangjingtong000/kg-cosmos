> **这份文档的存在本身就是项目主张的一部分**：宁可把短板写清楚，也不假装没有。
> 生成时间 2026-09-14。核查脚本：`tools/_probe/_audit_defects.py`；
> 原始产物：`data/quality/defect-audit-2026-09-14.json`。

## 0. 纠正：三个流传的数字不准确

| 说法 | 实测 | 说明 |
|---|---|---|
| "自环 3 条" | **4 条** | `PRODUCES` 2 条 + `RELATED_TO` 2 条 |
| "孤立节点 3450（22.5%）" | **7181（34.5%）** | 分母是**当前 20785 节点**口径（`l8-structure-audit.json` `connectivity.isolated_nodes`）；此前这里写 3036 / 分母 18780，是旧图读数 |
| "`CONTRIBUTED_TO` 165 条语义垃圾边" | **该关系类型在 Neo4j 里不存在（0 条）** | 见下方解释 |

**关于 `CONTRIBUTED_TO`**：`l8-structure-audit.json` 的 `predicate_space.caliber_warning`
写得很清楚——

> 入库后口径：越界谓词已被 `safe_relation_type` 改写为 `RELATED_TO`。
> **入库前有 147 种越界类型**，那一口径的简洁度约 15/161 ≈ 0.09。

所以 `CONTRIBUTED_TO` 这类越界谓词**在入库时被统一改写成了 `RELATED_TO`**。
Neo4j 里查不到它，是对的。**但代价是语义被泛化了**——见 §2。

## 1. 自环 4 条

```
MATCH (a)-[r]->(a) RETURN type(r), count(*)
  → PRODUCES   2
  → RELATED_TO 2
```

**是什么**：`a PRODUCES a` 这样的自指边，在语义上不成立（一个东西不能产出自己）。

**影响**：极小。4 / 45708 = 0.009%（评测全集口径）。

**为什么不直接删**：删掉会改动图规模，而**六层评测的所有数字都绑定在当前规模上**
（`README §5` 明确写了"跨口径比较前请先确认口径"）。为 0.009% 的收益
让全部指标失去可比性，不划算。

**建议**：如果要做，应当**先记下删前删后的两套指标**，而不是静默删除。
目前的做法是**如实记录在这里**。

## 2. `RELATED_TO` 是"泛化收容所"（最值得注意的一条）

| 项 | 值 |
|---|---|
| Neo4j 里有向 `RELATED_TO` | **4635 条** |
| 概览层无向去重后（`l8-structure-audit.json`） | 4268 条 |
| 入库前的越界谓词种类 | **147 种**（全部被改写成 `RELATED_TO`） |

**为什么这是缺陷而不是优点**：改写保证了"谓词一定在本体内"（L4 因此全通过），
**但代价是信息损失**——原来的 `CONTRIBUTED_TO`、`IS_BASED_ON` 之类的具体语义
全部塌缩成一个笼统的 `RELATED_TO`。

**这直接解释了 L4 的局限**：L4 只判"谓词在不在本体内"，不判"选对了没有"。
一个把 147 种具体关系全改写成 `RELATED_TO` 的管道，L4 通过率必然接近 100%
——**这不是质量好，是口径宽**。

**样本**：抽样 400 条 `RELATED_TO`，其中 **13 条（3.25%）是"别名式"**：

```
Unseen Classes      ↔ Seen Class
VQA                 ↔ OK-VQA
Image Classification ↔ Zero-shot Image Classification
Object Recognition  ↔ Zero-Shot Object Recognition
AwA                 ↔ AwA2 / AwA1
```

**这类边本该是"实体合并"**（`SAME_AS` 或别名归一），而不是一条关系。
它们的出现说明**实体归一还有漏网的近义/包含关系**。

**为什么不批量修**：与 §1 同理——会改动规模与全部指标。
且 3.25% 是从 400 条抽样得来的，**样本量不足以支撑全量改写**。

## 3. 孤立节点 7181 个（34.5%）

```
data/quality/l8-structure-audit.json → connectivity.isolated_nodes   → 7181
（分母 = 当前 20785 节点；旧图的 3036 / 分母 18780 已作废）
```

**是什么**：在图里没有任何一条边的实体。它们多数是"被抽成节点、但没有任何关系"
的实体——抽取器认出了它，但没能把它连进任何关系。

**影响**：这些节点在 3D 视图里会飘成"尘埃"（前端确实把它们标成 dust，
见 `nebula.json` 的 `dust: 1891`，口径不同：那个含"未归入社区"的）。

**为什么不删**：它们是**真实的抽取产物**，删掉等于掩盖 L3 端点 70.1%（抽取口径）
这个短板的成因。留在图里、并在这里说明，比删掉更诚实。

## 4. 与之对照：图**不是**随机堆出来的（正面证据）

同一份 `l8-structure-audit.json` 里有一条很硬的正面结论：

| 指标 | 实测 | 随机基线（10 次） | 比值 |
|---|---|---|---|
| 平均聚类系数 | **0.10553** | 0.000092 ± 0.000057 | **1150.05 倍** |
| 最大连通分量 | 12896（62.04%） | 19091.6（均值） | — |

**平均聚类系数是随机图的 1150.05 倍**（当前 20785 节点口径；旧图的 914 倍 /
597 倍已作废，见 `METRIC_CALIBERS.md §七`），说明这张图有真实的社区结构，
不是"随机撒点连边"。这条可以直接用在演示里回应"你怎么知道这图有意义"。
**但要与同一节的最大连通分量一起说**：62.04% 比随机图的 91.9% **更碎** ——
"社区结构真实"与"整体很碎"并存，只报前者是挑好看的。

## 6. 处理原则（本项目对此类问题的统一立场）

1. **不静默改数据**。任何改动都会让六层指标失去可比性，
   所以要么不改，要么"改前改后两套指标一起留档"。
2. **如实记录优先于消灭证据**。孤儿节点、泛化谓词、自环都是抽取管线的
   真实行为，删掉它们会让 `L3 = 68.4%` 这类结论失去成因。
3. **口径必须写清**。本文件所有数字都标注了来源与查询语句，
   且刻意区分了"入库前 / 入库后"、"有向 / 无向去重"两套口径。
