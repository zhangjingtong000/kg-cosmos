## 三、★ 一个能说明问题的细节

那 8 个 Playwright 脚本里，**有几个恰恰做的是"读 canvas 颜色缓冲"这种
听起来最像需要底层控制的事**：

```python
# cdp_verify_type_filter.py / cdp_verify_qa_to_3d.py 都在断言"颜色和真的变了"
cs = page.evaluate("() => window.__colorSample()")
# 同一层内：有高亮 57.5 → 清掉 649.108     ← 差 11 倍
```

**而它们用 `page.evaluate` 就做到了** ——
**不需要 websocket、不需要 `9222`、不需要手撸 CDP 的 message id。**

⇒ **所以"自建 CDP 能做而 Playwright 做不到"这个隐含理由是不成立的。**
当初用自建 CDP 更可能是**路径依赖**（第一版那么写了，后面就跟着抄）。

## 四、决定与理由

| 选项 | 做不做 | 理由 |
|---|---|---|
| **把 20 个老脚本重写成 Playwright** | ❌ | **功能等价、27 项全绿** ⇒ 重写是**纯风险换零收益**；<br>而且会**覆盖掉那些脚本里已经沉淀的坑位注释**（比如"`g.click()` 在 SVG 上不存在"、"CDP 脚本不能用 `window.__overlayRef`"） |
| **写清"为什么栈不同、边界在哪"** | ✅ | 这是 H8 的另一半，也是评审真正要的 |
| **★ 加守门：不许**新增**自建 CDP** | ✅ | **光写文档挡不住漂回去** |

**守门实现**（`tools/check_e2e_stack.py`）：识别每个 `cdp_verify_*.py` 用的是哪套栈，
**断言"自建 CDP"的数量不超过基线 20**。

- **只许减少**：真的把某个老脚本迁移了，就把基线改小（脚本会提示）；
- **不许增加**：新增 E2E 一律 Playwright。

⚠️ **这条检查不评价老脚本的质量** —— 它们**都还在回归里、都绿**。
它只拦"**明知有更省事的栈还继续手搓**"这一种情况。

## 五、诚实的边界

| # | 边界 | 影响 |
|---|---|---|
| **1** | **识别规则是正则**（`playwright` vs `websocket\|9222\|/json/list`） | 一个既用 Playwright **又**自己开 websocket 的脚本会被判成 Playwright；**没做人工逐个核对** |
| **2** | **"功能等价"是看回归绿灯得出的，不是逐条对照** | 严格说，自建 CDP 可能做到了一些 Playwright 脚本**没做**的事（如更细的网络拦截）；**没做能力对照表** |
| **3** | **老脚本一行没改** | 所以"技术栈与规划不同"这件事**在存量上仍然成立** —— 这一项只是**止损 + 说清**，不是"补齐" |
| **4** | **基线 20 是拍下来的** | 它只表达"**从今天起不许增加**"，**不表达 20 这个数合理** |
| **5** | **没有把 `check_e2e_stack.py` 接进 `verify_all` 之外的地方** | 它是回归里的一项；**如果有人绕过回归提交，它不起作用**（与所有回归项一样） |

**第 3 条最要紧**：**这一项没有让"栈不同"这件事消失** ——
它让**存量冻结、增量统一**，并把理由写下来。
**"要不要把 20 个老脚本也迁了"是个成本/收益的取舍，而按上面的账（纯风险换零收益），
答案是"不迁"** —— 但如果将来某个老脚本要改功能，**顺手迁过去**是应该的。
