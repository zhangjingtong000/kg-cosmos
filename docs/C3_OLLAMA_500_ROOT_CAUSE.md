## 二、★ 500 的来源：定位到了**具体一行**

```
src/kg_extractor.py
  L738  r = requests.post(f"{OLLAMA}/api/generate", json=payload, timeout=120)
  L739  r.raise_for_status()      ← **HTTP 500 在这里被抛出**
```

**两件事就此确定**：
1. **500 是 Ollama 自己返回的**（不是本项目的服务端，也不是前端）；
2. **116.2s 说明它跑了 116 秒才 500** —— **不是超时**
   （超时会抛 `requests.exceptions.ReadTimeout`，能区分开）。
   ⇒ **Ollama 是"接了活、干了一百多秒、然后失败"**，不是"根本没接"。

## 三、复现尝试：**连打 3 次，全 200**

```
第 1 次：200 · 82.2s · 显存前  895/8188 MiB   ← **模型未驻留**（要现加载）
第 2 次：200 · 62.9s · 显存前 6496/8188 MiB   ← 模型已驻留
第 3 次：200 · 62.7s · 显存前 6496/8188 MiB
```

（payload 与本地通道**逐字段一致**：`qwen3.5:9b` · `num_predict=2048` ·
`num_ctx=4096` · `enable_thinking=False` · 用 `l9-span-sample.json` 的真实文本。）

**⇒ 它是间歇性的** ⇒ 单跑几次复现不到。
⇒ 那么 500 更可能与**当时的机器状态**有关，而**不是这段代码**。

## 四、★ 复现过程中测到的那个数（**这是本轮最有价值的一条**）

```
模型未驻留：显存  895 MiB → 耗时 82.2s
模型已驻留：显存 6496 MiB → 耗时 62.7s
⇒ **6496 / 8188 = 79%**，**只剩 1692 MiB 余量**
```

**⇒ 强烈怀疑 500 是显存不足（OOM）**：
- Ollama 在显存不够时的失败表现**可能就是返回 500**；
- **而这解释了 TODO 里那句矛盾**："当场排查确认**显存空**" ——
  **排查发生在失败之后，那时模型多半已经卸载了**。
  **"排查时显存空"与"失败时显存不够"可以同时为真。**

**⚠️ 这是假设，不是结论。** 我没有做那个能判定它的实验，理由见下条。

## 五、⚠️ 我**没有**做 OOM 实验，以及为什么

**能判定的实验**是：**先占住显存**（再加载一个模型 / 让别的进程吃显存），
**然后打同一个长 prompt**，看会不会 500。

**我没做**：
- **它会让 Ollama 崩溃**（OOM 是它的失败模式之一）；
- **而用户不在电脑前** —— 崩溃了没人恢复，
  而且 `verify_all` 的 42 项里有 5 项依赖 Ollama。

**⇒ 交给用户的判别方法**（三分钟，可逆）：

```powershell
# ① 先占显存：把另一个模型拉起来并让它驻留
curl http://127.0.0.1:11434/api/generate -d '{\"model\":\"bge-m3\",\"prompt\":\"x\",\"keep_alive\":\"10m\"}'

# ② 看余量（应该明显小于 1692 MiB）
nvidia-smi --query-gpu=memory.used,memory.total --format=csv

# ③ 打同一个长 prompt，看会不会 500
python tools/_probe/_probe_ollama_500.py --n 2 --long

# ④ 清理
curl http://127.0.0.1:11434/api/generate -d '{\"model\":\"bge-m3\",\"keep_alive\":0}'
```

**判据**：如果**占着显存时必 500、清空后必 200**，
那就是 OOM，**根因确定**；否则我的假设被推翻，
要往"Ollama 内部错误"（看 `%LOCALAPPDATA%\Ollama\server.log`）方向查。

## 六、做了什么（**这一项的实际改动**）

给 `local_reextract_feasibility.py` 加了 **重试 + 错误分类**：

```python
RETRIES = 3
RETRY_WAIT = 10          # 给 Ollama 一点时间把显存理顺（假设是 OOM）
...
for attempt in range(1, RETRIES + 1):
    try:
        res = extract_chunk(...)
        break
    except Exception as exc:
        # **每次失败都打印**（HTTP 状态码也打出来）
        print(f'   ⚠️ 本地抽取第 {attempt}/{RETRIES} 次失败{extra}：{kind}: ...')
        time.sleep(RETRY_WAIT)
if res is None:
    raise SystemExit('❌ 连续失败 —— **不把它当成"抽到 0 条"**')
```

### ★ 关键设计：**重试绝不等于吞掉错误**

**最容易写错的一版是**：失败就当"抽到 0 条"，然后继续统计。
**那会变成静默降级** —— 而本脚本的**全部价值**就是
"**本地抽取到底行不行**"这个结论。

**把它静默成 0 条，等于替本地模型认了它没做的事** ——
**结论会看起来更差，而那是另一种谎。**
⇒ 所以：**每次失败都打印**（带 HTTP 状态码），**重试用尽后如实抛出**。

**这与 G3 那次是同一条纪律**：G3 修的是"404 也显示演示数据"，
这里防的是"500 也当成 0 条"—— **都是"别让失败伪装成结果"。**

**验证**：改完单跑 `--n 1`，结论与改动前一致
（金标 5 条 · 云端 30 条 · 本地 6 条 · 本地无净增益）⇒ **改动没坏。**
