# H2 · Schema 约束消融结果（2026-09-16）

> **配套**：`tools/schema_ablation.py`（可复跑）·
> `data/quality/schema-ablation.json`（产物）
>
> **一句话**：**在两段不同文本、两次独立运行上，「给不给关系类型的语义说明」
> 对谓词选择都**没有可测影响**。这与 P3 的协议阶梯互补：
> 起作用的是「**约束的存在**」，而不是「约束里写不写解释」。**

---

## 一、消融的**准确命名**（这一点必须说清）

TODO 里写的是「Schema 约束消融（开/关对比）」，但项目现有的开关
（`src/kg_extractor.py:598` 的 `KG_BARE_RELATION_TYPES`）控制的是：

```
=0（默认）  prompt 里给「类型名: 语义说明」（换行分隔）
=1          prompt 里只给「类型名」（逗号分隔）
```

**⇒ 两种都给了类型表**，只是给不给语义说明。
**真正的"完全不给类型表"需要改代码，本实验不做** ——
也不该顺手做：那会把「有没有约束」与「约束强不强」两件事混在一起。

⇒ 所以本实验的准确名称是「**关系类型语义说明的消融**」。

---

## 二、两次运行的结果

### 第一次：源文本前 3000 字符（`--offset-pct 0`）

| 指标 | 给语义（开） | 裸列表（关） |
|---|---|---|
| 实体数 | 22 | 22 |
| 关系数 | 16 | 16 |
| 用到的类型数 | 4 | 4 |
| **谓词落在本体内** | **100.0%** | **100.0%** |
| **`RELATED_TO` 兜底占比** | **6.2%** | **6.2%** |

类型分布 **逐条相同**：`PRODUCES` 10 / `ENABLES` 3 / `CREATED_BY` 2 / `RELATED_TO` 1。

**⇒ 但这一段是论文的标题页**（标题 + 作者 + 机构），
`PRODUCES` 占 62.5% ⇒ **关系类型单一，没有可区分的空间**。
（这正是第一次跑的教训：**取文本的偏移量不是可有可无的参数**。）

### 第二次：源文本 72% 处（`--offset-pct 0.72`）

| 指标 | 给语义（开） | 裸列表（关） |
|---|---|---|
| 实体数 | 17 | 17 |
| 关系数 | 6 | 6 |
| 用到的类型数 | 3 | 3 |
| **谓词落在本体内** | **100.0%** | **100.0%** |
| **`RELATED_TO` 兜底占比** | **16.7%** | **16.7%** |

类型分布**逐条相同**：`USES` 3 / `CITES` 2 / `RELATED_TO` 1。

## 三、结论

### ① 事实

**两段不同文本、两次独立运行，两种 prompt 下的输出**逐条相同**。**
不是"差异很小"，是**完全相同**。

### ② 为什么（机制解释）

**`CREATED_BY` / `USES` / `CITES` / `PART_OF` / `ENABLES` 这些类型名本身就是自解释的。**
给模型写「`CREATED_BY`: source 是创作者（作者/机构），target 是被创作物」
**没有增加它选对这一类所需的信息** —— 名字已经说完了。

⇒ **这是"语义说明冗余"的直接证据。**

### ③ ★ 与 P3 协议阶梯互补（这是本实验最有价值的部分）

| 实验 | 变的是什么 | 结果 |
|---|---|---|
| **P3 协议阶梯** | **完全开放** → **给类型表** | **α 从 −0.30 升到 +0.42**（分段提升） |
| **H2（本实验）** | **给类型表** → **给类型表 + 语义说明** | **无可测影响** |

**⇒ 合起来是一条更精确的结论**：

> **协议设计里起作用的是「约束的****存在****」，而不是「约束里写不写解释」。**
> **从"没有类型表"到"有类型表"是决定性的；从"有类型表"到"有带解释的类型表"是边际的。**

**这条对本体/prompt 设计的直接含义**：**先保证有明确的关系类型清单；
至于每类要不要配一段自然语言定义，在本地 9B 模型上可以不作为优化方向。**

## 四、诚实的边界

| # | 边界 | 影响 |
|---|---|---|
| **1** | **只跑了 2 段文本、各 3000 字符** | 样本极小；**但"逐条相同"是个强信号**，不像噪声 |
| **2** | **只用了 `qwen3.5:9b`** | 换模型（尤其更大的）可能有差异；**但也可能同样冗余** |
| **3** | **只测了"谓词选择"这一个下游指标** | **没测"实体抽取"** —— 语义说明也可能影响实体类型判断（未测） |
| **4** | **两段文本的关系类型都很少**（4 类和 3 类） | 类型多起来（如 10+ 类混用）时是否仍无差异，**未测** |
| **5** | **`RELATED_TO` 兜底占比不高**（6.2% / 16.7%） | 如果兜底率很高（说明模型选不出类型），语义说明可能有帮助 |

**第 5 条是最值得补的一个方向**：找一个**兜底率高**的样本
（即模型经常不知道该选哪类），在那里语义说明**可能**才会起作用。
**本次两段的兜底率都不高 ⇒ 没有触发那个条件。**
