# 金标标注操作指南（M2 实验前置）

> 规范依据：`GOLD_STANDARD.md`（评分口径与标注规则）
> 本文只讲**怎么动手**。目标：产出一份人工 ground truth，用于计算抽取质量
> P/R/F1 与错误类型分布。

## 0. 一句话流程

打开工作稿 → 对照 PDF 原文填两张表 → 交回 → 我转成 JSON → 自动评分。

## 1. 标注哪一篇

**`2012.00456v1`**（Knowledge Graph 基础设施主题，17 页、111 个文本块）。

选它的理由：篇幅适中（1–2 小时可完成）、实体类型多样（系统/组织/概念/数据集
都有），最能检验抽取器在类型判定上的边界。

## 2. 打开工作稿

```
`<仓库根>/data/gold/WORKSHEET-2012.00456v1.md`
```

文件里包含：

- **速查区**：15 类实体类型 + 15 类关系类型 + 填写格式 + 判定要点
- **正文区**：第 1–17 页的全部文本，按文本块切好并标了页码
- **建议范围**：前 10 页（60% 处）信息密度最高，优先标这里

同时打开 PDF 对照：
`<仓库根>/data/corpus/2012.00456v1.pdf`

> ⚠️ **标注时不要看系统的抽取结果**（`data/corpus/graphs/2012.00456v1.json`）。
> 看了会被锚定，金标就失去独立性，实验结论也就不成立。

## 3. 怎么填

在工作稿开头的两张空表里加行即可，用 `|` 分隔：

```markdown
| 实体名（规范名） | 类型 | 页码 | 原文依据（≤200 字符） |
|---|---|---|---|
| Open Research Knowledge Graph | System | 1 | "The Open Research Knowledge Graph (ORKG)..." |
| Research Contributions | Concept | 1 | "...publishes the research contributions..." |

| 源实体 | 目标实体 | 关系类型 | 页码 | 原文依据 |
|---|---|---|---|---|
| ORKG | Research Contributions | PRODUCES | 1 | "...publishes the research contributions..." |
```

**四条判定要点**（细则见 `GOLD_STANDARD.md` §2）：

1. 只标明确写出来的：泛指词（"the model"）、纯编号（"Table 1"）、只在参考文献
   列表出现的条目不标
2. 同一实体的不同写法记一条，取论文里的**全称**（`multi-head attention`，不是 `attention`）
3. 关系两端必须是本篇**已标注的**实体，且句中有明确文字依据
4. 没把握的隐含关系**不标**——金标宁缺勿错（漏标只会略微低估 Recall，错标会
   污染 Precision）

**工作量目标**：实体 50–100 条、关系 30–60 条。填到 100 条实体就够用了，
不必把 17 页全部标完。

## 4. 交回后我做什么

1. 把 Markdown 表格转成 `data/gold/2012.00456v1.json`（结构见 `GOLD_STANDARD.md` §4）
2. 跑评分脚本：对系统在该篇上的抽取结果算
   - 实体 P / R / F1（严格口径 + ≥0.93 相似度宽松口径）
   - 关系 P / R / F1 + 方向错误数
   - 四类错误分布：幻觉 / 类型错误 / 边界错误 / 遗漏
3. 这份金标同时用于：四通道对比、Schema 消融、D1 双代理审计验证

## 5. 时间与成本

- 标注：约 1–2 小时人工（不花 API 钱）
- 评分脚本运行：几秒，零 API 调用

## 6. 如果时间不够

**最小可行版本**：只标前 5 页、实体 40 条、关系 20 条。仍能算出有意义的
P/R/F1，只是置信区间更宽。论文里注明标注范围即可。
